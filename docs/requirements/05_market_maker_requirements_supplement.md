### 2. 做市商退出机制

#### 2.1 主动退出流程
```
用户申请退出
    │
    ▼
┌─────────────────┐
│ 检查挂单状态    │
│ (需撤销所有挂单) │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 检查持仓状态    │
│ (需平仓所有持仓) │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 结算剩余费率优惠 │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 冻结期(7天)     │
│ 保留历史考核数据 │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 状态变更为      │
│ WITHDRAWN       │
└─────────────────┘
```

#### 2.2 冷静期
- 退出后**7天冷静期**，期间可以恢复
- 冷静期结束后，需重新申请（无需审核，直接恢复原等级）
- 历史考核数据保留6个月

#### 2.3 退出限制
- 有未结算的费率优惠时不允许退出
- 有强平风险时不允许退出
- 有未完成的订单时不允许退出

### 5. 市场异常保护机制

#### 5.1 极端行情保护
```
检测条件:
- 5分钟内价格波动 > 10%
- 或交易量暴增 > 5倍
- 或深度快速消失 > 80%

保护措施:
1. 自动扩大做市商最大价差限制（临时）
2. 暂停做市商考核计算（该时段）
3. 启用保险基金保护
4. 强平优先级降低
```

#### 5.2 系统故障保护
- 系统故障期间，自动暂停考核
- 故障恢复后，补偿做市商损失
- 提供故障报告和补偿方案

#### 5.3 熔断期间规则
- 熔断期间，做市商可选择：
  - 保持原有挂单
  - 或自动撤销所有挂单
- 熔断期间不计入考核时间

### 6. 数据隔离与安全

#### 6.1 订单数据保护
- 做市商订单不显示在公开Order Book的前10档
- 仅显示聚合后的深度
- 防止被狙击

#### 6.2 交易数据隐私
- 做市商身份在公开接口中隐藏
- 成交数据脱敏处理
- 禁止泄露做市商名单

#### 6.3 API安全
- 强制使用TLS 1.3
- API Key定期轮换（90天）
- 支持IP白名单绑定
- 异常登录自动冻结

### 9. 降级与熔断策略

#### 9.1 服务降级
```
Level 1: 负载 > 70%
- 限制批量订单数量（100 → 50）
- 增加响应时间容忍度

Level 2: 负载 > 85%
- 关闭非核心API（查询类）
- 仅保留下单/撤单接口

Level 3: 负载 > 95%
- 启用熔断
- 拒绝新订单
- 通知所有做市商
```

#### 9.2 熔断机制
- **触发条件**:
  - 系统CPU > 95% 持续30秒
  - 数据库连接池耗尽
  - Kafka消息积压 > 100万

- **熔断动作**:
  - 停止接受新订单
  - 允许撤单操作
  - 推送熔断通知

- **恢复条件**:
  - 系统负载恢复正常
  - 人工确认系统健康

## 📊 新增数据模型

### 10.4 做市商争议表 (t_mm_dispute)
```sql
CREATE TABLE t_mm_dispute (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id             BIGINT NOT NULL COMMENT '用户ID',
    dispute_type        VARCHAR(32) NOT NULL COMMENT '争议类型',
    -- PERFORMANCE: 考核结果争议
    -- FEE: 费率计算争议
    -- OTHER: 其他

    related_id          BIGINT COMMENT '关联ID（考核ID/费率流水ID）',
    description         VARCHAR(1024) NOT NULL COMMENT '争议描述',
    evidence            TEXT COMMENT '证据（JSON）',

    status              VARCHAR(16) DEFAULT 'PENDING' COMMENT '状态',
    -- PENDING: 待审核
    -- APPROVED: 已通过
    -- REJECTED: 已拒绝

    reviewer_id         BIGINT COMMENT '审核人ID',
    review_comment      VARCHAR(512) COMMENT '审核意见',
    reviewed_at         TIMESTAMP COMMENT '审核时间',

    created_at          TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    KEY idx_user_id (user_id),
    KEY idx_status (status),
    KEY idx_created_at (created_at)
) ENGINE=InnoDB COMMENT='做市商争议表';
```

### 10.5 做市商激励记录表 (t_mm_incentive_log)
```sql
CREATE TABLE t_mm_incentive_log (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id             BIGINT NOT NULL COMMENT '用户ID',
    incentive_type      VARCHAR(32) NOT NULL COMMENT '激励类型',
    -- NEW_SYMBOL: 新品种激励
    -- LIQUIDITY_AWARD: 流动性奖励
    -- LONG_TERM_AWARD: 长期合作奖
    -- EXTREME_MARKET: 极端行情保护

    amount              BIGINT NOT NULL COMMENT '激励金额',
    symbol              VARCHAR(32) COMMENT '关联交易对',
    period_date         DATE COMMENT '激励周期',

    status              VARCHAR(16) DEFAULT 'PENDING' COMMENT '状态',
    -- PENDING: 待发放
    -- SETTLED: 已发放
    -- CANCELLED: 已取消

    settled_at          TIMESTAMP COMMENT '发放时间',

    created_at          TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    KEY idx_user_id (user_id),
    KEY idx_incentive_type (incentive_type),
    KEY idx_period_date (period_date)
) ENGINE=InnoDB COMMENT='做市商激励记录表';
```
